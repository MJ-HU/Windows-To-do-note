# 任务栏备忘 (TaskbarMemo)

贴在任务栏上的一条备忘。双击完成当前一条，右键出菜单。

- 单文件 `exe`，无安装程序、无外部依赖、不写系统目录
- 只用 Windows 自带的 .NET Framework 4.x，不需要装 .NET SDK 或其他运行时
- 数据存在 `%APPDATA%\TaskbarMemo\data.xml`，卸载就是删掉 exe 和这个文件夹

---

## 一、编译

双击 **`build.cmd`** 即可。它会调用系统自带的 C# 编译器：

```
%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe
```

产物：`TaskbarMemo.exe`（几百 KB），双击运行。

> 如果 `build.cmd` 报"找不到 csc.exe"，说明这台机器没装 .NET Framework 4.x。
> Windows 10 / 11 全都自带，一般不会遇到。

也可以手动编译。在已打开的 `cmd` 窗口里，`cd /d` 到本目录后，**整行**粘贴：

```bat
"%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /nologo /target:winexe /platform:anycpu /optimize+ /codepage:65001 /out:TaskbarMemo.exe /r:System.dll /r:System.Drawing.dll /r:System.Windows.Forms.dll /r:System.Xml.dll src\*.cs
```

`/codepage:65001` 不能省：源码是 UTF-8，不指定的话 csc 会按系统 ANSI 代码页
（简体中文机器上是 GBK）去读，界面上的中文全部变乱码。

> `build.cmd` 刻意写成**纯 ASCII、无 `chcp`、无 `^` 续行、无括号块、无 goto**。
> 原因：这个文件是 LF 换行的，而且在 .bat 里执行 `chcp 65001` 会让 cmd 后续按
> 错误的字节偏移读文件，把 `cd /d` 吃成 `/d`、把 `"%CSC%"` 吃成 `csc.exe`。

## 二、显示位置

任务栏有两种行为模式，在 **设置 → 显示位置** 里切换：

### 模式 A：贴着任务栏（默认）

窗件被画在**任务栏内部的空白区域**——托盘左边那一段，高度与任务栏一致，
配色跟随系统深浅色主题。它不遮挡任何应用窗口，视觉上就是任务栏的一段。

**单行内分成三个分区**，从做到右依次是：自定义 | 常规 | 远期。
每个分区最左边有一条类别色条（蓝=自定义，黄=常规，绿=远期），
右侧显示该分区的进度 `1/3`。某个分区当天没有待办时不会占位，
剩下的分区自动平分整条宽度。

双击某个分区，只完成那个分区当前显示的这一条，其余分区不受影响。

以下情况会**自动退回模式 B**（不会留一个错位的窗件）：

- 任务栏设为自动隐藏
- 任务栏竖着放（贴在屏幕左/右侧）
- 托盘左侧剩余空间不足 120 像素
- 系统里找不到任务栏窗口

**这不是 deskband。** 真正的 deskband 是注册进 Explorer 的 COM shell 扩展，
需要 ATL、要区分 32/64 位，而 Win11 的新任务栏已经彻底移除了 deskband 支持。
现在这个做法是"在任务栏的空白位置画一个置顶小窗"，效果上等价，代价是：
如果任务栏按钮多到排满、或者按钮一直排到托盘左边，窗件会盖住最右边那个按钮。

### 模式 B：浮在托盘上方

悬浮卡片形式，宽度 300，高度随分区数自动变化（1~3 行）。
每个分区占一行，会盖住桌面右下角一小块。模式 A 无法满足时自动使用这个。

## 三、使用

### 窗件操作

| 操作 | 效果 |
|---|---|
| 左键双击某个分区 | 完成**那个分区**当前的这条，显示该分区的下一条 |
| 右键 | 弹出菜单 |
| 右键托盘图标 | 同一个菜单 |
| 双击托盘图标 | 把窗件叫回来 |

没有待办时显示"今日无待办备忘"；当天全部做完显示"今日备忘已全部完成"。

### 三种备忘

**1. 自定义备忘**（一次性）

右键 → 自定义备忘，多行文本框，**一行一个**，空行忽略。
每条独立，双击完成后永久消失。再次打开只会看到还没做完的那些。

**2. 常规备忘**（按周几，每天可写多条）

右键 → 常规备忘。周一到周日 7 个页签，每天一个 **多行文本框**：

```
┌─ 周一 ─┬─ 周二 ─┬─ 周三 ─┬ ... ┐
│ ☑ 这天启用      一行一条，可以写多条 │
│ ┌───────────────────────────────┐ │
│ │ 开周会                        │ │
│ │ 审上周的数据                   │ │
│ │ 给客户回邮件                   │ │
│ └───────────────────────────────┘ │
└───────────────────────────────────┘
```

- **一行一条**，所以同一天可以写任意多条，各自独立完成
- 点"这天启用"控制该天是否显示（内容保留，随时可重新勾上）
- 留空 = 这天没有任务
- 每天的内容完全独立，互不影响
- 当天双击完成后**当天隐藏，第二天自动重新出现**

**3. 远期备忘**（指定日期，同一天可写多条）

右键 → 远期备忘。选好日期，在多行输入框里写内容，**一行一条**，点"添加"。

- 一次可以加多条，它们都挂在同一个日期上
- **只在设定的那一天**出现，当天可以逐条显示、逐条双击完成
- 过了那天还没做完就不再显示（条目还在列表里，可以改日期或删掉）
- "更新"会把选中的那一条替换成输入框里的每一行（第一行沿用原条目的完成状态）
- **"清空输入"** 只清空输入框，不动列表
- **"全部删除"** 一次删掉列表里所有远期任务（会先确认，显示条数）

三个分区从左到右排列：自定义 → 常规 → 远期。

### 设置

右键 → 设置：

1. **滚动**：按设定秒数让**每个分区各自**轮换到自己的下一条。只是切换显示，
   不会标记完成，必须双击才算完成。某分区只有一条时不会轮换。
2. **显示内容**：自定义 / 常规 / 远期，可多选。
3. **显示位置**：贴着任务栏 / 浮在托盘上方。
4. **开机后自动启动**：两级实现。
   先写注册表 `HKCU\...\CurrentVersion\Run`（当前用户、无需管理员、不弹 UAC）；
   注册表被系统拒绝时，改写到启动文件夹
   `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\TaskbarMemo.cmd`。
   两条都失败会明确弹窗告知，不会静默失败。
   注意：走启动文件夹那条路时，开机会先闪一下命令行窗口（`.cmd` 的固有行为）。
   在只允许写单一目录的受限环境里，注册表和启动文件夹可能都不可写，
   此时开机自启无法实现——这是环境限制，不是程序缺陷。

## 四、数据与可靠性

### 文件

```
<数据目录>\
├─ data.xml                   当前数据（备忘 + 设置）
├─ data.bak.xml               上一份数据，自动保留
├─ data.corrupt-<时间>.xml    读坏时留档（正常不会出现）
└─ error.log                  异常日志
```

**右键 → 数据位置** 会显示当前数据目录并把路径复制到剪贴板。
这里刻意**不启动 explorer 进程**：受限机器上新起进程会失败（0xc0000142），
强行打开只会弹一个没用的系统错误框。要打开就自己把路径粘到资源管理器地址栏。

### 数据目录是分级回退的

早期版本把数据固定写到 `%APPDATA%\TaskbarMemo`，在个别机器上那个位置写不进去，
而异常被静默吞掉，表现出来就是"关机后全没了"。现在按顺序尝试：

1. `%APPDATA%\TaskbarMemo`（漫游，首选）
2. `%LOCALAPPDATA%\TaskbarMemo`（漫游被重定向/不可写时的常见退路）
3. `exe 同目录\TaskbarMemoData`
4. `%TEMP%\TaskbarMemo`
5. 注册表 `HKCU\Software\TaskbarMemo`（文件系统彻底写不了时兜底）

保存时同样按这个顺序逐个试，**第一个成功的位置就是以后的落点**，并会在启动时
优先从已有数据的位置读取。文件系统全线失败时用注册表兜底，所以只要还能改
当前用户的注册表，数据就不会丢。

### 保存策略

每次改动立即落盘，不是退出时才存。每个位置内部还分两级：

1. 先写 `data.xml.tmp`，用 `File.Replace` 原子替换成 `data.xml`，
   旧的自动变成 `data.bak.xml`
2. 原子替换失败（被占用、权限、杀软锁定等）→ **直接覆盖写** `data.xml`

只有两级都失败才换下一个位置。全部位置都失败才弹窗，且弹窗里会显示
**真实异常文本**，不再是一句无从下手的"保存失败"。

### 读取策略

1. 各位置的 `data.xml`，成功就用
2. 失败 → 把原文件改名成 `data.corrupt-<时间>.xml` 留档（**绝不原地覆盖**），
   然后弹窗告知
3. 再试 `data.xml.tmp`（写入中断时留下的完整数据）
4. 再试 `data.bak.xml`
5. 再试注册表
6. 全失败才退回空数据

### 读取策略（这一版重点修的地方）

旧版本有个会把数据吃掉的缺陷：读失败时静默返回空数据，然后下一次保存
就把原文件覆盖了。现在的顺序是：

1. 读 `data.xml`，成功就用
2. 失败 → 把原文件改名成 `data.corrupt-<时间>.xml` 留档（**绝不原地覆盖**），
   然后弹窗告知
3. 再试 `data.bak.xml`，成功就恢复
4. 都失败才退回空数据

保存失败会**弹窗**提示并给出数据目录，不再静默吞掉。

## 五、关于"无法验证发布者"的安全提示

首次运行可能弹出 **"打开文件 - 安全警告：无法验证发布者"**，每次启动都问一遍。

这**不是"没签名"导致的**——未签名的本地 exe 是静默运行的。真正原因是文件的
**Mark of the Web（下载标记）**：NTFS 上附加了一个 `Zone.Identifier` 数据流，
Windows 据此认定"这个文件来自 Internet"，于是每次启动都确认一次。
被同步/备份软件处理过的目录（比如 `D:\Backup\...`）容易出现这种情况。

### 去掉它

**办法一（手动，一次搞定）**：右键 `TaskbarMemo.exe` → 属性 → 常规页底部
勾选 **"解除锁定"** → 确定。

**办法二（自动）**：`build.cmd` 编译成功后会做一次"复制 → 删除原文件 → 把干净副本移回"，
新建的文件不带备用数据流，标记就没了。

如果去掉后每次重新编译又出现，说明有同步/备份软件在给文件重新打标记，
需要把该目录排除掉，或者每次编译后手动解除锁定。

> 代码签名只能把"发行商"从"未知发布者"变成真实名字，**不能消除这个提示**，
> 而且新证书首次运行还会触发 SmartScreen 的声誉拦截。所以这里没有做签名。

## 六、已知限制

- 模式 A 里，任务栏按钮排满时会盖住最右边一个按钮
- 多显示器时只看主显示器的任务栏
- 高分屏（125%/150%）下程序是 DPI 不感知模式，尺寸正确但略微软
- 程序**没有代码签名**，首次运行 SmartScreen 会提示"未知发布者"，
  点"更多信息 → 仍要运行"即可
- 任务栏重启（Explorer 崩溃重启）后，窗件位置由 2 秒一次的定时器自动纠正

## 七、文件结构

```
TaskbarMemo/
├─ build.cmd              一键编译（纯 ASCII，勿加 chcp）
├─ README.md
└─ src/
   ├─ Program.cs          入口、单实例、全局异常兜底
   ├─ Models.cs           数据结构 + 日期工具
   ├─ Store.cs            XML 持久化、备份、损坏留档、错误日志
   ├─ AutoStart.cs        开机自启（注册表 Run 键）
   ├─ Shell.cs            任务栏几何探测（P/Invoke）+ 深浅主题
   ├─ UiFont.cs           中文字体挑选
   ├─ Gfx.cs              圆角路径 + 程序内生成的托盘图标
   ├─ TextWrap.cs         中英混排按字折行
   ├─ MemoForm.cs         窗件（任务栏条状 / 悬浮卡片两种形态）
   ├─ Dialogs.cs          四个对话框：自定义 / 常规(7天) / 远期 / 设置
   └─ TrayContext.cs      托盘、菜单、今日队列、位置维持、计时器
```
